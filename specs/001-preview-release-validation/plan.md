# 实施计划 · 0.6.0 预览版验收

- **分支** `chore/spec-kit`
- **日期** 2026-11-18
- **规格** [spec.md](spec.md)

## 摘要

在候选提交 `0840f82` 上验证安装和真实模型任务。继续用旧评测入口复现 11 月 9 日基线，并用 0.6.0 主入口补做端到端验证。恢复任务按原判定执行，单独记录脚本及人工证据。

## 技术背景

- **语言与依赖** Python 3.11 或更新版本、Git、pytest 和候选源码包。
- **运行及存储** 本机 Windows 执行，隔离仓库、事件和报告保存到 Git 忽略的 `.cache/nano-eval/`。平台 CI 覆盖 Windows、Linux 和 macOS。
- **调用预算** 采用评测器已有配置。I01 最多 5 次模型请求，其余每项最多 9 次。修复或功能候选通过差异检查后独立运行测试。
- **范围** 固定的八个自动任务、两个恢复任务、候选版本安装和已有入口验收。第二模型及外部试用按可用条件记录。

## 项目原则检查

评测使用隔离副本和既有授权规则。验证读取实际报告、文件差异和终端行为。规格限定于当前预览版验收。计划复核通过。

## 项目结构

- `coding_agent/` 提供候选包、主入口、兼容入口与自动测试。
- `evals/` 保存固定任务、评测器、恢复驱动和对比结果。
- `specs/001-preview-release-validation/` 保存本轮规格、证据约定与任务状态。

## 执行顺序

1. 记录候选提交，确认源码包可安装、单元测试及离线任务可复现。
2. 先执行 I01，再逐项执行 N02、N03、N04、I05、I06、N07、I08。审阅候选后用同一评测器验证。
3. 使用主入口验证一个真实只读任务。执行恢复脚本，并在真实终端补做两项人工恢复验收。
4. 汇总通过、失败和未执行项，登记候选提交的跨平台证据、第二模型和外部试用。
