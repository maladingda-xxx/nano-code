# 功能规格 · 0.6.0 预览版验收

- **分支** `chore/spec-kit`
- **创建日期** 2026-11-18
- **状态** 验收中
- **依据** [产品开发计划](../../plan.md)的 0.6 预览版验收要求。

## 使用场景与测试

### US1 · 维护者复现真实任务基线（P1）

维护者需要知道当前候选版本能完成哪些真实开发任务，以及失败发生在哪里。

在固定的两个目标仓库版本上运行现有八个自动评测任务，并独立验证修复和功能任务的补丁。

1. 每次运行都能追溯到候选版本、目标提交、模型、请求预算和最终结果。
2. 只读任务须符合原有证据和无修改判定。修复及功能任务须通过独立测试，且改动局限在规定范围内。

### US2 · 使用者验证恢复行为（P2）

使用者需要在异常退出后辨别上次执行状态，并在撤销时保留后续手工修改。

从隔离副本运行 N09 和 N10，核对终端提示及文件内容。

1. 强制退出并重启后，能够查看未结束轮次并辨别已知结果和待核查操作，写入标记恰好出现一次。
2. 撤销遇到后续手工编辑时保留当前内容。移除冲突后再次撤销，只移除本轮写入，保留原有用户修改。

### US3 · 试用者验证安装与模型接入（P3）

试用者需要能独立安装和启动候选版本、接入模型并完成至少一个真实开发任务。

分别记录干净环境安装、平台测试、模型端到端验证和外部用户试用的结果。

1. 记录 Windows、Linux、macOS 的自动验证结果，以及计划要求的两种模型服务的任务证据。
2. 外部试用者在自己的仓库里独立使用，并记录执行结果、审批、等待或恢复问题。

### 边界情况

- 请求失败或超预算时保留退出原因和报告。
- 模型自述完成、修改验收测试、修改越界或仅产生候选补丁时，按实际证据判定结果。
- 脚本化恢复和用户实际操作分别记录，平台或模型缺少验证条件时标为待验收。

## 需求

- **FR-001** 固定当前 Nano Code 候选提交及既有评测目标提交，并记录每项任务的耗时、用量、差异和验证结果。
- **FR-002** 复用既有任务与预算，提交候选补丁后由独立评测器验收。
- **FR-003** 记录 N09 和 N10 的恢复状态、用户可见提示和文件内容核对结果。
- **FR-004** 记录候选版本的安装、两种模型服务、三种目标平台和外部试用的实际验证范围。

## 成功指标

- **SC-001** 8 个自动任务全部有可追溯结论。完整固定任务集至少通过 8 项，保留所有失败记录。
- **SC-002** 2 个恢复场景完成人工操作验收，并核对每个场景的终端提示和文件内容。
- **SC-003** 3 个目标平台和 2 种模型服务均有可追溯验证记录，外部试用反馈进入发布记录。
