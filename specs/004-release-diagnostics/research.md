# 调研 · 发布诊断与版本记录

## 1. 导出入口形式

- **决策**：在现有 `nano-code doctor` 上增加 `--export <路径>` 选项。
- **理由**：`doctor` 当前作为位置参数解析，新增选项不改变原有调用；`nano-code doctor` 继续输出 JSON，`nano-code doctor --export diag.json` 写文件并返回路径。交互式 `/doctor` 保持只读展示。
- **备选方案**：新增 `doctor export <路径>` 子命令。需要改动现有位置参数解析，且容易与 prompts 混淆，不采用。

## 2. 脱敏策略

- **决策**：递归遍历导出对象；字段名匹配 `api_key`、`token`、`secret`、`password`、`authorization` 的字符串值替换为 `[REDACTED]`；自由文本中的常见令牌前缀（`sk-`、`gho_`、`github_pat_`、`Bearer ...`）也替换。布尔字段 `api_key_configured` 保留，用于说明是否配置。
- **理由**：诊断字段由代码显式构造，本身不包含 Key 值；递归脱敏为未来新增字段和扩展错误文本提供保护。保留布尔值不影响排障。
- **备选方案**：白名单式只导出固定字段。更安全但每次新增字段都要改白名单；当前实现已显式构造字段，递归脱敏足够，并用测试锁定。

## 3. 数据格式版本

- **决策**：在 `session_store.py` 增加 `SESSION_FORMAT_VERSION = 1`，通过 `diagnostics()` 暴露，并在 `CHANGELOG.md` 记录。
- **理由**：当前会话数据库兼容 v0.3 存档布局，但没有显式格式编号。先提供可查询的版本号和文档，不引入迁移器。
- **备选方案**：立即实现数据库迁移框架。当前没有格式变更需求，属于过度设计。

## 4. 存储与清理文档

- **决策**：在 `docs/terminal.md` 的升级和排查部分列出用户配置、项目设置、会话数据库和文件快照的位置，说明备份、删除影响和清理步骤。
- **理由**：会话数据库同时保存对话、工具输出和文件快照，删除会影响 `/sessions`、`/resume`、检查点和撤销，但不改变工作区文件。用户需要在清理前理解影响。
- **备选方案**：单独新增存储文档。终端指南已是用户入口，集中说明更易发现。

## 5. 版本记录

- **决策**：在仓库根目录新增 `CHANGELOG.md`，记录 0.6.0、0.3.1、0.3.0 和 0.2.0 的主要变更、已知限制和数据格式版本。
- **理由**：`plan.md` 是产品路线图，不适合逐版本发布记录；独立 CHANGELOG 更符合发布习惯。
- **备选方案**：只依赖 Git 历史。用户安装后无法快速了解版本差异，不采用。
