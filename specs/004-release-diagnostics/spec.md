# 功能规格 · 发布诊断与版本记录

- **创建日期** 2026-11-18
- **状态** 已完成
- **候选版本** Nano Code `0.6.0`
- **依赖** [发布收尾](../003-release-closeout/spec.md)

## 使用场景与验收

### US1 · 支持者导出可安全分享的诊断记录（P1）

用户在遇到模型、依赖或项目环境问题时，需要把当前配置和运行环境交给支持者。诊断记录必须包含定位问题所需的信息，同时不能包含 API Key、令牌或其他凭据值。

**独立验收**：配置一个 API Key 后执行导出命令，生成的文件是有效 JSON，包含版本、环境、配置路径和检查结果，且不包含该 Key 的任何片段。

**验收场景**：

1. **Given** 已配置 API Key 和模型，**When** 运行 `nano-code doctor --export diag.json`，**Then** 生成 `diag.json`，内容包含版本、数据格式版本、平台、模型和检查结果，且不出现 Key 值。
2. **Given** 导出路径不可写或指向目录，**When** 执行导出，**Then** 命令返回非零并给出可读错误，不留下半截文件。
3. **Given** 未配置 API Key，**When** 执行导出，**Then** 文件仍生成，`api_key_configured` 为 `false`。

### US2 · 使用者能查到版本、数据格式和清理方式（P2）

使用者需要知道当前版本、会话数据格式、设置和会话数据保存在哪里，以及如何安全清理。升级或排查前能据此备份和删除数据。

**独立验收**：从版本记录和终端文档中能查到 0.6.0 的变更、数据格式版本、设置文件、会话数据库和文件快照的位置及清理步骤。

**验收场景**：

1. **Given** 用户查看版本记录，**When** 找到 0.6.0，**Then** 能看到主要能力、已知限制和数据格式版本。
2. **Given** 用户要清理会话数据，**When** 查看终端文档，**Then** 能找到数据库位置、备份方式、删除影响和重启要求。
3. **Given** 用户运行 `nano-code doctor`，**When** 查看输出，**Then** 能看到数据格式版本。

### 边界情况

- 诊断记录是本地文件，不上传、不自动发送。
- 脱敏是尽力而为：已知的密钥字段名和常见令牌前缀会被遮蔽，用户分享前仍应自行审阅。
- 导出只读取当前进程配置，不连接模型服务，不产生模型费用。
- 数据格式版本本轮只做暴露和记录，不引入迁移逻辑。
- 不改变现有 `nano-code doctor` 的 JSON 结构和退出码语义。

## 需求

### 功能需求

- **FR-001**：`nano-code doctor --export <路径>` 把诊断记录写入指定文件；成功后返回 `0`。
- **FR-002**：导出内容包含版本、数据格式版本、Python 与平台、工作区、服务商、模型、推理强度、权限模式、配置目录、会话数据库路径、Skills/MCP 摘要和检查结果。
- **FR-003**：导出内容不得包含 API Key、令牌、密码或完整凭据值；只允许出现是否已配置的布尔值。
- **FR-004**：诊断记录对字段名或文本中匹配 `api_key`、`token`、`secret`、`password`、`authorization` 的内容做遮蔽；已知前缀（如 `sk-`、`gho_`、`github_pat_`）即使出现在自由文本中也要遮蔽。
- **FR-005**：`nano-code doctor` 的现有输出增加数据格式版本，不破坏已有字段。
- **FR-006**：新增版本记录，至少包含 0.6.0 的变更、已知限制和数据格式版本。
- **FR-007**：终端文档说明设置文件、用户配置目录、会话数据库、文件快照的存储位置，以及备份、删除和清理步骤。
- **FR-008**：新增回归测试覆盖导出成功、路径错误、缺失 Key 和脱敏行为；现有测试保持通过。

### 关键实体

- **诊断记录**：版本、数据格式版本、环境、配置、扩展摘要、检查结果；不含凭据值。
- **数据格式版本**：当前会话数据库和文件快照的格式编号，用于记录和诊断。
- **存储位置**：用户配置目录、项目设置、会话数据库和会话内快照。

## 成功标准

### 可衡量结果

- **SC-001**：导出命令在 1 秒内完成一次本地诊断，生成文件为有效 JSON。
- **SC-002**：使用包含 API Key 的配置导出，Key 值在导出文件中出现次数为 `0`；新增测试自动验证。
- **SC-003**：版本记录和终端文档覆盖 100% 的存储位置及对应清理步骤。
- **SC-004**：现有 82 项测试继续通过，新增测试覆盖 4 条关键路径。

## 假设

- 本轮只提供命令行导出，不增加交互式 `/doctor --export`。
- 数据格式版本从当前会话数据库格式开始记为 `1`；不实现迁移器。
- 版本记录采用仓库根目录的 `CHANGELOG.md`，不替代 `plan.md` 的历史证据。
- 导出路径由用户指定，可以是工作区外路径；程序不创建父目录。
